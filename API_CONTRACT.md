# 3iLens local API (contract v3)

Frontend: Next.js App Router at `http://localhost:3000`. Backend: FastAPI (port 8000 by default; `start.bat` may use 8001). JSON keys use snake_case. Scores, mastery, urgency and costs are computed on the backend. All demo records carry `is_demo: true`; live uploads always use real AI providers and never fall back to sample grades.

**Source of truth for every JSON shape: `frontend/src/lib/types.ts`.** `backend/schemas.py` mirrors it field for field and `backend/tests/test_contract.py` checks both the names and every live payload against it. Contract v2 is additive: no v1 field was renamed or retyped. New response fields are always present (nullable fields are `null`, lists default to `[]`); rows written by older builds are filled with defaults when read.

Code layout: core routes in `main.py`; AI + analytics in `routers/analytics_routes.py`; pipeline + ops in `routers/pipeline_ops.py`; outputs in `routers/outputs.py`; contract v3 routes in `routers/ai_ops.py`, `voice_routes.py`, `lms.py`, `owner_routes.py` and `insights_routes.py`. Every route below is implemented. The UI still renders an empty state (never crashes) when a call fails or returns an unexpected shape.

## Conventions

- **Errors.** Bodies are `{detail: string, code?: string}` (`ApiErrorBody`). Coded errors use `errors.ApiError(status, detail, code)`; codes are snake_case. v1 detail texts are unchanged. Use `errorCode(err)` / `errorMessage(err)` from `lib/api.ts`.
- **Timestamps** are ISO-8601 UTC. Report run ids and calendars use India Standard Time (`Asia/Kolkata`, fixed +05:30).
- **Internal file paths are never sent to the UI.**
- **Labelled simulations.** WhatsApp delivery is SIMULATED everywhere (statuses `BLOCKED_TEMPLATE_PENDING` / `SIMULATED_NOT_SENT`; never "sent"). The chapter-weightage matrix, the mixed NEET demo rubric and every ROI projection are sample/illustrative (`IllustrativePill`). The OCR engine is Claude vision as a PoC stand-in for Google Vision (`Health.ocr_adapter`).
- **OCR cache wording** (FR-2.5, on by default): a cache hit is shown in the UI and the audit log as `OCR cache hit - no vision call (Rs 0.00)` (`provenance.OCR_CACHE_HIT_LABEL`).
- **Bulk re-evaluation** after a rubric edit must be confirmed in the UI first, showing the number of students and the estimated cost from `GET /api/rubrics/{id}/reevaluation-estimate`.
- **Typed DOCX answer sheets** go through the same PDF -> vision route as scans (no separate text path).
- **Urgency rule** (one rule everywhere, `analytics.classify_urgency`): score >= 70% `on_track`, 55-70% `needs_attention`, < 55% `at_risk`; one level worse (capped at `at_risk`) when 2 or more topics have mastery < 40%. Urgency is `null` unless the submission is COMPLETED.
- **Exam date.** A batch with no exam date uses `NEET_EXAM_DATE` (default `2027-05-02`) and reports `exam_date_assumed: true`; the UI labels it "assumed". `days_to_exam` counts IST days (null when past). Strategy: >= 90 `broad`, 30-89 `focused`, 7-29 `revision`, 0-6 `consolidation`.
- **AI errors.** Provider failures reach the API as 502 with the provider error code (e.g. consistency check, rubric parse): `timeout`, `connection`, `rate_limited`, `provider_unavailable` (transient), `refusal`, `empty_response` (these six send an OCR / grading / voice-mapping call to the GPT-4o fallback once - never a tick-reader call, see Upload; if it fails too, the Claude error stands and transient errors are retried with backoff), `truncated`, `invalid_json`, `auth`, `permission`, `model_not_found`, `bad_request`, `too_large`, `api_error`, `ai_error`; voice adds `empty_transcript`; the outage drill records `simulated_outage`. A missing key is 503 `ai_not_configured`.
- **`Submission.last_error_code`** (FAILED rows) is one of the AI codes above, `ai_not_configured`, a pre-processing code (`corrupt_pdf`, `password_pdf`, `no_pages`, `too_many_pages`, `corrupt_image`, `corrupt_docx`, `unsupported_signature`, `upload_missing`), `custody_mismatch` (the stored file no longer matches its SHA-256), `no_transcript`, `evaluation_inconsistent`, `schema_mismatch`, `interrupted` (the server stopped mid-run; marked FAILED on the next start so an operator can Retry) or `internal_error`.
- **Human-review gate** (FR-2.4): `OCR_CONFIDENCE_THRESHOLD` (default 0.70) applies to the whole sheet and to every page; any page below it holds the sheet for faculty review. A page's confidence is the model's legibility rating for that page, else the mean confidence of the answers mapped to it. A file name containing `blurry` still pauses before any pre-processing or AI call at confidence 0.65. The gate (`pipeline.review_decision`, pure) decides in this order and stores the reason in `Submission.review_reason`: (1) the same-paper check found another code / set (`paper_reordered`) or another paper / not this paper's rubric (`paper_mismatch`) - detail = the check's message; (2) no rubric question has a non-empty answer, no page is below the threshold and the sheet is at or above it -> `no_answers`, detail `No answers found for rubric '<name>' (<version>): none of its N questions has a transcribed answer although the pages read clearly (page legibility 85-90%) - check that the sheet was uploaded with the right rubric; routed to faculty review; AI evaluation skipped.` (voice: `No part of the recording could be mapped to a question of rubric ... - routed to faculty review; AI evaluation skipped.`); (3) sheet below the threshold -> `low_confidence` (`OCR confidence x is below the y threshold ...`); (4) any page below it -> `low_page_confidence`; (5) a document sheet with an answer for fewer than half of the rubric questions -> `mostly_blank`. Sheet confidence (`ocr_confidence`): the OCR's overall confidence, except when no rubric question has an answer and pages were assessed - then the mean page legibility, rounded to 3 places (a mean over zero answers is not a confidence; log `Extracted 0 answer(s); no rubric question has an answer, so the sheet confidence is the page legibility 0.87; page confidence p1 0.90, ...`). `ocr.json` keeps the model's raw `overall_confidence`. A voice answer with nothing mapped keeps 0.0 (no pages) and is held as `no_answers`.

The files are kept with the new snapshot (see Rubric sources below; Ingestion log `Answer key drafted from question paper <name> (PDF, 19 pages) and answer key <name> (text, 1 page) - kept with rubric '<name>' (custom-N) for preview.`, the paper named by its role: `question paper`, `rubric file` or `marked copy`). There is no default rubric: neither `rubric_json` nor `rubric_id` -> 422 `rubric_required` (`Add the question paper or the answer key - every upload needs its own answer key (rubric).`), checked before the file is stored. Validates everything before saving; the SHA-256 is computed while streaming and stored with size, page count, language hints, `student_ref` (roll no upper-cased, else a name slug) and the intake id. PDF/JPEG/PNG/WEBP/DOCX (typed DOCX is converted to PDF pages and read by the same vision route); max 20 MB and `MAX_PDF_PAGES` PDF pages (default 40). A PDF / DOCX whose printed text looks like a printed MCQ paper or a question paper with its answer key gets one extra Ingestion log line (`Printed MCQ paper detected ...` / `This file looks like a question paper with its answer key ...`); processing never changes. Answer sheets are printed or typed, never handwritten. A sheet answered on a printed MCQ paper is read by the tick reader (`mcq_marks.py`, prompt `marks-v4`; `pipeline.ocr_reader`) when the rubric is all MCQs with 10+ questions (one written question sends the sheet to the transcription reader) and the upload is a PDF of 3+ pages, a PDF whose text layer `paper_detect` reads as `question_paper` / `answer_key_paper`, or a JPEG / PNG / WEBP photo or scan (a Word file never): for every printed question it reports the option the student ticked, circled or shaded, `MCQ_OCR_PAGES_PER_CALL` pages per call (default 5) with the next page as context, `AI_CHUNK_CONCURRENCY` calls at a time (default 5), from the `PDF_MASTER_DPI` masters (default 200) re-encoded at 1800 px; printed keys are ignored, options (1)-(4) score as A-D, and two chunks reading different options cap the confidence below the gate. **No cross-vendor fallback for ticks:** a live run on gpt-4o moved ticks and filled blanks (304/720 vs 402) at 0.95 confidence, so a Claude error is not sent to `LLM_FALLBACK_MODEL` - a transient one goes to the pipeline's retry with backoff, and a sheet that still fails is FAILED with **Retry** (never wrong marks); with `VISION_PROVIDER=openai` the reader uses `OPENAI_VISION_MODEL` directly. The reader also returns each printed question's first words and the printed paper code; when the rubric has no question text (a key-only rubric) it skips the first words and returns instead each question's NCERT chapter, one of the 80 names in the `syllabus` of `data/weightage/neet.json` (Physics 28, Chemistry 20, Biology 32; a name whose subject does not fit the rubric question's is dropped), saved as `question_chapters` in `ocr.json`; `pipeline.chapter_rubric` then grades a copy of the rubric with each question's chapter as its `topic` and `chapter` (subject kept; never when the rubric already has question text or chapters), so topic mastery, focus rows, ROI and the study plan are per chapter (log `... (by the chapter of each printed question - the key has no question text)`). In full mode `paper_match.compare` checks the first words (when read) and the code against the rubric (log `Paper check: ...`, saved as `paper_check` in `ocr.json`) and holds a sheet whose questions are in another order (another code / set) or from another paper in `HUMAN_REVIEW_REQUIRED` with that message, unscored; approving it in the review editor scores it with the rubric anyway. A PDF / Word file read by the transcription ("handwriting") reader (a Word file, or a PDF the tick reader does not take; fresh OCR or OCR-cache hit alike) gets the same check from its text layer with no AI call (`pipeline.document_paper_check`; full runs that are not a rescan; never fails the job): only when `paper_detect.printed_paper` reads its text layer as a printed paper (an `answer_key_paper`, or a `question_paper` with option lists for at least half of its numbered questions - a typed answer sheet with a few (a)-(d) sub-parts is not checked), the verdict of intake inspect is used (`paper_detect.rubric_check` -> `paper_match.paper_check`): the printed question text compared with the rubric wins when it holds (another paper / version) or finds the rubric's questions on the paper (`paper_match.found_on_paper`: `match`, or `unknown` that compared at least one question and matched at least 60% of them - e.g. a rubric for one section of the paper; only logged). That comparison's hold verdict holds the sheet only when fewer than half of the rubric questions have a transcribed answer; otherwise it is set aside (`review_decision(..., text_layer=True)`, the typed text is the student's answers) and logged `Paper check: not applied - n of N rubric questions have a transcribed answer, so the document's text is read as the student's answers, not another paper's questions.`. When the comparison cannot tell (no comparable question text, verdict `unknown`), `paper_match.shape_check` holds - whatever was transcribed - a printed paper of 10+ numbered questions against a non-MCQ-heavy rubric with fewer than half as many questions as `paper_mismatch` (`This is a printed question paper with about 174 numbered questions, but rubric 'Biology - Genetics' (v1) has 5 questions, none of them MCQs - it is not this paper's rubric. Re-run the sheet with the paper's rubric, or approve it to score it with this rubric anyway.`). Logged as `Paper check: ...` and saved as `paper_check` in `ocr.json`; the OCR call still runs (approving the held sheet grades its transcript). Other sheets longer than `OCR_PAGES_PER_CALL` pages (default 10) are transcribed in page chunks, each later chunk with the previous page as context only, `AI_CHUNK_CONCURRENCY` calls at a time (one `ocr` invocation per chunk); if any chunk is served by the fallback the whole OCR is labelled `openai` and not cached. A repeat upload of identical bytes logs `Same file bytes as submission #N` and, with `OCR_CACHE=1` (default), reuses the cached OCR (`OCR cache hit - no vision call (Rs 0.00)`). |

### Scoring (`marking.py`, `bloom.py`, `insights.py`)

- **MCQ** (`question_type: "mcq"`, FR-4.8): scored by option letter only; MCQs are never sent to the grading call (an all-MCQ paper makes no grading call) and the answer key is never sent to OCR. Correct `+max_marks`; wrong or more than one option `-negative_marks` (question value, else `marking_policy.negative_marks`, clamped 0..max); blank `0`; unreadable (`UNKNOWN`) `0` with "check the sheet". `estimated_marks` is net and may be negative; `penalty` carries the deduction. The outcome of a wrong MCQ is `ZERO`. Totals are net sums (may be negative); `overall_mastery` and topic mastery are clamped to 0-100.
- **Descriptive** (FR-3.8): with no policy and no scheme the original rule is unchanged (clamp, round half-up to 0.5). `marking_policy.partial_credit` / per-question `partial_credit`: `steps` (round to `mark_step` 0.25 / 0.5 / 1 / 2), `proportional` (2 dp), `all_or_nothing`. With a `marking_scheme` and per-step `criteria_awards` from the grader, each step is clamped and rounded, then summed; a `required` step below 50% of its marks scores the question 0. A scheme without awards uses the overall marks (noted in `marking_note`).
- `scoring_controls.marking_rule` = the original text for rubrics without MCQs or a policy, else a composed sentence, e.g. `NEET +4/-1 (sample): MCQs +4 correct, -1 wrong, 0 blank; descriptive partial credit in 0.5-mark steps; totals summed server-side`.
- **Bloom K1-K5** (FR-3.9): rubric `bloom_level` (source `bloom_source`, default `faculty`) else a verb heuristic over the prompt (source `heuristic`; highest-level verb wins; default K2). The Genetics demo resolves to Q1 K3, Q2 K2, Q3 K2, Q4 K3, Q5 K1. `demonstrated_level` comes from the grader (null for MCQs and blanks). The grading prompt (`eval-v3`) carries each question's level, scheme steps and partial-credit rule.
- **Consistency check** (`POST /api/results/{id}/consistency-check`) scores the re-grade through the same engine: MCQs keep their deterministic marks from the transcript (no false delta), scheme questions are re-scored from the re-grade's step awards.
- **Teacher action plan**: when the grader gave no intervention for a topic, the template names the first missed rubric criterion; for a topic whose lost marks are all MCQs it names the missed MCQs and the -1 rule instead of the scoring criteria. Templates are rebuilt at read time.
- Legacy and seeded rows gain the new question keys at read time (`marking.annotate_questions`); they are never re-scored.

### Rubric authoring additions (`RubricQuestion`, `RubricContent`)

`question_type?`, `options?` (2-6 strings, MCQ only), `correct_option?` (normalised to one letter; required for MCQs; must be within the options), `negative_marks?` (MCQ only, 0..max), `bloom_level?` (`"apply"` -> `K3`; anything else 422), `bloom_source?`, `concept?` (<= 200), `marking_scheme?` (`MarkingStep[]`, 1-20 steps, descriptive only, marks must add up to `max_marks`: `Q<n> marking_scheme marks (x) must add up to max_marks (y)`), `partial_credit?`, `mark_step?`; `RubricContent.marking_policy?` (`MarkingPolicy {partial_credit, mark_step, negative_marks, scheme_name?}`). An MCQ without `expected_answer` / `grading_criteria` gets `Option X` / one generated criterion; a scheme without criteria gets one per step. All new fields default to absent, so every existing rubric's stored content and `rubric_hash` are byte-identical. Invalid values -> 422 `invalid_rubric` (upload, create, version). AI rubric drafts (`rubric-v2`) carry `question_type`, `options`, `correct_option` and an AI-proposed `bloom_level` (`bloom_source: "ai"`); drafts with MCQs get the NEET +4/-1 policy labelled "default - confirm with academic lead".

**Several accepted options and bonus MCQs.** `RubricQuestion` += `accepted_options?` (MCQ only; 2-6 distinct letters A-F within the options, read like `correct_option` and stored in letter order; null, absent or `[]` = unused) and `bonus?` (MCQ only; default false and left out of the stored content while false, so existing hashes hold). An MCQ needs `correct_option`, or `accepted_options`, or `bonus: true`; with `accepted_options` the `correct_option` is null or one of them; a bonus may have no `correct_option`. Errors (422 `invalid_rubric`): `Qn is an MCQ: correct_option is required (one option letter A-F), unless it has accepted_options or is a bonus`, `Qn accepted_options needs 2-6 option letters (a single answer is correct_option)`, `Qn accepted_options must not repeat an option`, `Qn accepted_options must be option letters A-F within the options`, `Qn correct_option X must be one of accepted_options (B or C)`, `Qn bonus|accepted_options is only allowed when question_type is 'mcq'`. Missing `expected_answer` / criteria become `Option B or C` / `4 marks for option B or C; ...` and `Bonus question` / `4 marks to every student (bonus question)`. Scoring (`marking.score_mcq`): a bonus scores full marks with no penalty whatever was marked, blank included (note `Bonus question - full marks to everyone (+4)`); with `accepted_options` any accepted option scores full marks (`Accepted options B or C (+4)`), another option is wrong (`Marked D, accepted B or C (-1)`), and blank / several marked / unreadable follow the usual rules. `QuestionEvaluation.correct_option` is the student's own option when it scored full marks, else the key's `correct_option`, else the first accepted letter; `outcome` is `FULL` for a bonus, blank included (it scored full marks: it is left out of the PDF appendix of questions without full credit and counted as full in `outcome_counts` / topic counts). Rule texts name them (`Q51, Q53 accept more than one option; bonus Q71, Q98: full marks to everyone`). Answer-key entries (`marking.parse_answer_key`) read `2 or 3`, `B/C`, `(1), (3)` and options written back to back with no separator - `(2)(3)`, `(B)(C)`, `b)c)` - as `accepted_options` (`(b) mitochondria` stays one option and its text); the same tokens in a student's answer are `MULTI` (several options marked). `marking.is_bonus_key` reads `Bonus`, `*`, `Dropped`, `Deleted`, `Cancelled`, `Grace`, `All options correct`, `All are correct`, `Any option` as a bonus (never `All of the above`, an option text). AI drafts (`rubric-v3`, `rubric-pages-v3`) read `2 or 3` as `accepted_options` and `Bonus` / `*` / `dropped` as `bonus` - also when the model writes one of those bonus words into `correct_option` (or `accepted_options`) and leaves `bonus` false (`ai._draft_key`) - with the warnings `More than one accepted option for Q51 (B or C), ... - any of them scores full marks; check before approving.` and `Bonus (full marks to everyone): Q71, Q98 - check before approving.`

### Student report redesign (additive; server-built summary blocks)

Every headline number on `/report/<id>` and page 1 of the PDF comes from the server with one formula and one format: percentages always carry 1 decimal and are computed from the unrounded score / max (`55.8%`, `40.0%`, `73.9%`); marks are whole when whole; negative marks use the real minus sign (U+2212). MCQ papers use one vocabulary - right / wrong / blank / bonus; full / partial / zero stay for written answers. One band system everywhere: `analytics.classify_urgency` (At risk < 55%, Needs attention 55-70%, On track >= 70%, one level worse with 2+ topics below 40%).

- **QuestionEvaluation** += `accepted_options: string[]` (every letter the key accepts: `["B","C"]` for Q51 "B or C", `["B"]` for a single key, `[]` for written answers; `correct_option` stays the first accepted letter for back-compat) and `result_kind` (`right` | `wrong` | `blank` | `bonus` | `partial` | `zero`; MCQ: bonus first, then blank when no option was marked or none is readable, right at full marks, else wrong; written: blank / right (full marks) / zero / partial). Both are written at grading time and filled at read time for stored rows (`marking.annotate_questions`, `marking.result_kind`); `QuestionEvaluationOut` also fills them for any payload that lacks them.
- **OutcomeCounts** += `right, wrong, bonus, attempted` (result_kind counts; `attempted` = answered non-bonus questions). On an MCQ paper right + wrong + blank + bonus = total_questions; `full` = right + bonus. `mapped` is a faculty figure.
- **SubjectRollup** += `right, wrong, blank_scorable, bonus, bonus_marks, attempted, attempt_rate` (attempted / (questions - bonus), fraction 0-1), `accuracy_attempted` (right / attempted, 0-1), `penalty`, `marks_dropped` (max - score), `gain_to_target` (max(0, 0.85 x max - score)), `band` (urgency thresholds on the subject %), `diagnosis` (`solid` >= 70%; else `skipping` when blanks >= 2 x lost answers, `wrong_answers` when lost answers >= 2 x blanks, else `mixed`). `pct` is 1 decimal from the unrounded ratio.
- **Result** += `key_insights: KeyInsight[]` (exactly 3 when built, `[]` on older payloads), `score_band: ScoreBand | null`, `focus_topics: FocusTopics`, `student_summary: string[]`. Built by `analytics.result_extras` (each block guarded: a bug logs and falls back to its default) and so present on archived versions too. `strengths_gaps` is cleaned at read time: per-MCQ lines such as `Q2 (Physics): Correct option A` are replaced by topic-level lines (`Biology: right on 68 of 78 answered`, `Physics: 19 blank and 8 wrong of 45`); written-answer lines are kept. Student cards use the same clean-up.
- **KeyInsight** `{id: attempts|subjects|gain, tone: good|warn|neutral, headline (<= 90 chars), detail, figures: KeyInsightFigure[] {key, label, value, unit (marks|questions|%), formula}, evidence: KeyInsightEvidence {kind: questions|subject|topic, filter: wrong|blank|null, refs: number[], subject, topic, anchor}}`. `anchor` is the element id on the page, without `#` (`questions`, `subject-physics`, `focus-physics`). With R = right, W = wrong, Bl = blank, Bn = bonus, A = R + W, P = sum of penalties, S = score, T = total:
  - **attempts (I1)**: blank_marks = marks of the blank questions (a ceiling, never the expected gain); headline in order `No questions answered` (A = 0), `Wrong answers are costing you -P marks` (P > 0 and R/A < 0.35), `Skipping, not wrong answers, is holding your score back` (Bl / (N - Bn) >= 0.15 and R/A >= 0.5), else `Your attempt strategy is working`. With negative marking (+M / -N per question, modal values) the detail gives the realistic value of the blanks - break-even = N / (M + N), half the blanks narrowed to two options = Bl / 2 x (0.5 M - 0.5 N) - and the attempt rule. Report 1: `47 questions left blank. With +4/-1 marking, answer whenever you can rule out one option (break-even is 20% sure): narrowing half the blanks to two options is worth about +35 marks, 188 at most. You were right on 80.2% of what you answered (105 of 131); wrong answers cost only 26 marks.` Figures: blank, likely_gain, break_even, blank_marks, penalty, score_without_wrong, accuracy. A paper with no negatively-marked questions reads `Where marks went: partial credit X marks short, blanks Y marks`.
  - **subjects (I2)**: strongest = max %, weakest = min % (ties: more max_marks / more marks dropped); a single-subject paper compares chapters. `Physics is your weakest subject, mostly from skipping` / `Physics 64/180 (35.6%): you answered 26 of 45 and got 18 right (69.2%). Strongest: Biology 266/360 (73.9%).`
  - **gain (I3)**: one target with the score card (`analytics.focus_target`): the band's target (the 70% On track line, or the batch target) while the student is below it, else the 85% stretch target. At chapter level when topic_mastery has 2+ topics that are not just their subject, else per subject; g = max(0, target x max - score) from unrounded marks. Below the target: the fewest areas (largest g first, at most 5) whose gains reach it - report 1: `Path to On track: Physics and Chemistry to 70%` / `Physics to 70% (126/180) adds +62 and Chemistry to 70% (126/180) adds +54: 402 + 116 = 518/720 (71.9%), past the On track line (504). Biology is already at or above 70%.` At or above it: `Biggest gain: X, about +g marks` to 85%. Everything at the target: `Keep it up - lowest area X at Y%`.
  - **highlight** (string | null): the number in `detail` the page highlights (`+35`, `518/720`).
  - The web report and the PDF show `student_summary` as "In short" and, when it has 3 lines, only the insights it does not cover (I1); I2 and I3 stay in the payload.
- **Web report views** (`/report/<id>`, no API change): a student view (score card with `score_band`, `student_summary`, `key_insights`, subject cards, `focus_topics`, the question grid; study plan, exam technique, chapters, question details, sheet pages and the batch comparison folded under "More details") and a teacher view that adds the faculty folds (review and release, re-grade / re-run with an inline key, rubric sources, study-plan lab, teaching actions and interventions, reading quality, processing and audit). A shared link opens in the student view; `?view=teacher|student`, a deep link to a faculty fold or the viewer's last choice (browser storage) picks the view.
- **ScoreBand** `{key, label, pct, thresholds: ScoreBandRange[] {key, label, from_marks, to_marks, from_pct, to_pct} (cut points 55% and 70% of the total), target_marks, target_pct, target_source: on_track_line|batch_target, marks_to_target, right_answers_to_target (ceil(marks_to_target / the paper's usual question marks)), batch_median_marks (median of the other completed students on the same test and batch, demo with demo; null below 5 peers)}`. `key` is the urgency (one band system). Report 1: 396 / 504 cut points, target 504, 102 marks, 26 right answers.
- **FocusTopics** `{level: chapter|subject, chapters_available, reason ('Chapter breakdown is not available for this paper yet.' at subject level), target_pct (the I3 target: 70 for report 1), rows: FocusTopicRow[] (<= 5, only areas below the target), keep_warm: {topic, subject, mastery}[] (areas already at the target, <= 5), keep_warm_more}`; **FocusTopicRow** `{topic, subject, n, score, max_marks, mastery (1 decimal, unrounded ratio), right, wrong, blank, marks_dropped, gain (same g as I3), action: learn|drill|review (from the diagnosis: solid -> review; skipping, or below 40% -> learn; wrong answers -> drill; mixed -> learn when blanks >= lost answers), what_to_study (names the counts and the first 3 refs of each list: 'Learn the Physics basics behind the 19 you skipped (Q1, Q4, Q5, ...), then redo the 8 you got wrong (Q15, Q16, Q18, ...).'), question_refs (blank first for learn, else wrong first), wrong_refs, blank_refs, low_evidence (n < 3)}`. Sorted by gain, then mastery. Broad-mode study-plan actions follow the same diagnosis (learn / drill / maintain).
- **student_summary**: score + band + gap to the target, strongest / weakest subject, the next step - no OCR / coverage line and no question lists. `executive_summary` stays the faculty narrative (MCQ papers now count `105 right, 26 wrong, 2 bonus`).
- **StudyPlan** += `planned_minutes_total` (sum of every `weekly_calendar` block, checkpoint included: the one planned-time number; `allocation_note` states it, `Next 18 h: the calendar plans 4 h 15 min (255 min) - Physics 90 min · ...`). **PlanTopic** += `minutes` (that topic's calendar minutes). While a `priority_focus` topic is in the plan, a `no_action` / `maintain` topic gets at most one 30-minute refresher block all week. Gains and projections use the unrounded mastery (score / max): report 1 projects to 85.0, Physics gains 89.0; `gain_high` is capped at exam_marks x (100 - mastery) / 100 and, for a whole-subject topic, at the paper's remaining marks (max - score). `days_to_exam` is never clamped. Calendar notes cite at most 5 refs, wrong first.
- **RoiBasis** += `effort_source_kind` (`matrix` | `rubric` | `placeholder`): `placeholder` when a focus topic's effort is the 1 h rubric default or a whole subject - the UI and PDF then hide effort hours and ROI per hour.
- **NegativeMarkingProfile** += `bonus_questions: number[]`, `bonus_marks`, `reconciliation: {net_answered (right x marks - penalties), bonus_marks, total}` (report 1: 394 + 8 = 402); the blank advice uses one denominator, `47 of 178 scorable MCQs (2 bonus excluded) were left blank`.
- **FatigueProfile**: `early_accuracy` / `late_accuracy` are now on ANSWERED non-bonus questions (blanks are the blank rates), and accuracy only counts when each side has at least min(5, half its scorable questions) answers. += `within_subject: SubjectPacing[]` `{subject, first_from, first_to, second_from, second_to, first_right, first_attempted, second_right, second_attempted, first_accuracy, second_accuracy (0-1 or null), change_pts}` (first half vs second half of each subject section), `within_subject_change_pts` (question-weighted), `confounded_by_section` (2+ subjects each in one block: the paper-wide split compares subjects, so `flagged` / `severity` rest on the within-subject change). Reasons read `Accuracy rose 21 pts in Q121-Q180` / `fell X pts` - never a negative drop.
- **BloomBucket**: `marks` is now NET (penalties included; the levels add up to the score) and += `marks_before_penalty`. **StudentPatterns** += `bloom_informative` (2+ levels and not every tag the heuristic default); the UI hides the Bloom card when false.
- **Student PDF** (`reports.render_student_pdf`, `RENDER_VERSION` `sair-pdf-v6` in `routers/outputs.py`): page 1 = header (name, batch, test, date, days to the exam), the plain-language provisional notice, "In short" (`student_summary`), score + band + a drawn bullet chart (grey bands, navy measure, amber target), the key insights "In short" does not cover, the subject table (right / wrong / blank / bonus / answered % / right-when-answered % / marks) and the top focus rows; then the question grid (MCQ papers; bars for written answers), chapters (when present), the week's study plan, exam technique (negative marking per subject, the reconciliation line, pacing within each subject, Bloom only when informative), then for faculty the teaching actions and the illustrative study-plan lab (ROI, quadrants, projected gain, roadmap), Appendix A, and a closing 'Processing, coverage and sign-off' section with the run metadata (run id, OCR adapter, rubric hash, cost). No run id in the footer.

## Data reset (`scripts/reset_data.py`)

Run from the repo root with the backend venv python: `backend\.venv\Scripts\python.exe scripts\reset_data.py [--yes] [--db PATH] [--root DIR]` (defaults: `backend/3ilens.db`, the repo root holding `uploads/`, `artifacts/` and `backups/`). Works while the backend is running (SQLite WAL); exit 0 = done or dry run, 1 = failed with nothing deleted.

- **Dry run** (default, read-only): rows that would be deleted per table (model invocations as `N of M (only rows tied to a sheet)`, batches as `N of M (no kept row uses them; the base batch stays)`), a `Batch changes:` list naming each batch to delete (`delete batch NEET-B / Mock-08`) and each demo faculty lead to clear (`clear faculty lead 'Dr. A. Rao (demo)' of batch NEET-A / Mock-07`), the kept tables with their counts, and how many items / bytes would move out of `uploads/` and `artifacts/`.
- **`--yes`**: (1) `BEGIN IMMEDIATE` on the live database - the backend's writes wait until the commit; (2) SQLite backup API copy to `backups/<UTC yyyymmddThhmmssZ>/<db name>` (read through a second connection; WAL content included); (3) checks that the copy opens, passes `PRAGMA quick_check` and has the same row count in every table; (4) moves everything in `uploads/` and `artifacts/` except `.gitkeep` (the kept rubric sources in `artifacts/rubrics/` included) into the backup folder; (5) deletes, in the same transaction and in foreign-key order: `rubrics`, `student_submissions`, `ocr_cache` (all rows) and every table that references them - `evaluation_results`, `evaluation_versions`, `ocr_reviews`, `deliveries`, `intervention_records` (all rows) and `model_invocations` rows with a `submission_id` (found from `PRAGMA foreign_key_list`, so a later table is covered too), then every `batches` row except the base `NEET-A` / `Mock-07` that `seed.seed_base` creates and any batch a kept row still references, and sets `faculty_lead` to NULL where it contains `(demo)` or `(sample)`; (6) commits and prints the deleted counts and `Demo faculty leads cleared: N`. Kept: `institutions`, the base batch, `api_keys` and model invocations of no sheet (rubric drafting). Any failure rolls the deletion back and moves the files back. `backups/` is git-ignored.
